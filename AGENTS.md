- Multi-restaurant: rows carry restaurant_id; RLS scopes to active restaurant_members; rooms/tables writable only by master. Invites use a token server function so staff cannot self-register. Pages in src/routes/_authenticated; hooks in src/lib/data.ts.
- Customer reliability is derived from reservation attendance and service deadlines in Europe/Rome; only manual no-show is persisted, and normalized phone is the history key to avoid duplicate counters and name-based identity.
- Agenda layout: agenda-wide CSS variant (landscape ≥768px, desktop ≥1024px) drives toolbar and page visibility, for orientation consistency.

- Shared service data uses one restaurant-scoped root Realtime subscriber with wildcard cache invalidation, so every date/view updates together, including DELETE and reconnect.
- Reservation operator audit is populated by a database trigger from active membership, not client-supplied labels, so attribution cannot be forged.
- Offline app shell is generated by vite-plugin-pwa; guarded registration excludes previews and OAuth, while private query snapshots are account/restaurant-scoped in sessionStorage for 60 seconds and cleared on sign-out.
- Emergency exports are self-contained escaped HTML from loaded query data, downloadable offline.
- Printed service sheets use service-sheet.ts for chronological sorting, repeated headers and print-only CSS.
- Service deletions set reservations.deleted_at; active reads exclude deleted rows, while permanent customer deletion removes linked records. Assigned tables are uuid[] on reservations, so deletion frees tables.
- Walk-in creation, recycle-bin restoration and live-mode seating on freed tables use authenticated security-invoker RPCs with restaurant-scoped locking and interval checks, preserving RLS and trusted audit attribution.
- Account deletion goes through the SECURITY DEFINER RPC delete_own_account(): it removes the caller's restaurant_members row and auth.users row while audit survives on copied operator-name text; the last active master of a restaurant is blocked from self-deletion.
- Keep .env tracked in git (never in .gitignore): it holds only publishable keys and the published build reads VITE_* values from it; ignoring it ships a blank site.
- Tenant isolation: operational queries and cache keys use the active restaurant ID from tenant.ts; absent IDs fail closed. Global reads only on the guarded /admin page, since Super Admin RLS bypass must never merge operational data.
- Self-profile edits use a narrow authenticated database RPC deriving the caller from auth.uid(); operational_role is descriptive and never changes Master/Staff permissions. The profile reads actual account membership, not the synthetic assistance membership.
- Settings: one Master-only /settings tab hub reusing shared editors; menu opens ServiceHub/Live via search flags, no duplicate pages.

- Room scheduling is independent of the map lock; optimistic writes target the exact restaurant-scoped query key and refetch after persistence to prevent stale checkbox state.
- Room flags sync by DB trigger; seats mirrors coperti_comodi. Allocation/reorganization share assignment-rules and canJoin; DB forbids island unions; Gemini drafts stay unsaved until Master confirms; tavolo_bloccato pins bookings. Reorganization never overlaps intervals: unplaced bookings stay pinned on current tables.
- Public online booking uses narrow RPCs exposing only branding and aggregate availability; insertion validates tenant, cutoff, capacity and consent atomically under restaurant lock. Public pages use sessionless publishable clients, no management banners.
- Online requests hold aggregate capacity while pending; operational queries and customer reliability read only confirmed rows. Decisions use a tenant-authorized locking RPC, so rejected requests never occupy tables and direct status edits are blocked.
- Restaurant delivery credentials are encrypted server-side and kept in a service-only configuration store; SMTP accepts only approved public provider hosts with mandatory TLS, so tenants cannot probe arbitrary destinations.
- Editable numeric controls keep string drafts until blur or submission; shared NumberInput preserves numeric persisted state without coercing empty keystrokes.
- Online double-turn windows are restaurant configuration, enforced by the same database predicate in slot listing and atomic submission; duration and cleaning buffer protect the second turn, while public results expose only aggregate slots and turn labels.
- Booking email templates and staff destination live in the protected restaurant delivery settings; trusted reservation events derive recipients and tenant-scoped placeholder data server-side, never from a generic browser send endpoint.
- Voice dictation: per-restaurant OpenAI/Gemini key encrypted (AES-GCM, AAD ai:<id>) in service-only restaurant_ai_settings; parsing in authenticated server functions only after transcript confirmation; pure date rules override AI arithmetic, falling back to the agenda date.
- Monthly agenda calendar gestures are opt-in through CalendarDayGesture; pointer timers and a shared same-cell tap tracker suppress consultation clicks on navigation, leaving other date pickers unchanged.
- Live floor (src/lib/live-floor.ts): states from arrived flags and rotation intervals; occupied tables use seat_walkin_freed, earlier-than-booking seating uses seat_walkin_limited (server-side max_stay_until + shorter duration_min).
- Custom rules use strict JSON and legacy adapters; allocation.ts shares deterministic assignment. One text stores one confirmed bundle; tenant-locked fingerprints prevent recent duplicates.
