- Multi-restaurant: data rows carry restaurant_id (defaults to my_restaurant_id()); RLS scopes to active membership in restaurant_members; rooms/tables writable only by role master. Invites are accepted via a token server function (admin createUser) so staff cannot self-register into a restaurant. Pages live under src/routes/_authenticated; data hooks in src/lib/data.ts.
- Assigned tables are stored as uuid[] on reservations, so deleting a reservation frees its tables automatically.
- Customer reliability is derived from reservation attendance and service deadlines in Europe/Rome; only manual no-show is persisted, and normalized phone is the history key to avoid duplicate counters and name-based identity.
- Agenda layout uses the agenda-wide CSS variant for landscape screens from 768px and desktops from 1024px; keep toolbar and page visibility on the same variant to preserve orientation consistency.

- Shared service data uses one restaurant-scoped root Realtime subscriber with wildcard cache invalidation, so every date/view updates together, including DELETE and reconnect.
- Reservation operator audit is populated by a database trigger from active membership, not client-supplied labels, so attribution cannot be forged.
- Offline app shell is generated by vite-plugin-pwa; guarded registration excludes previews and OAuth, while private query snapshots are account/restaurant-scoped in sessionStorage for 60 seconds and cleared on sign-out.
- Emergency exports are self-contained escaped HTML built from loaded query data, so they download without a network call and preserve room/table ordering.
- Service deletions set reservations.deleted_at without clearing the row; every active reservation read excludes deleted rows, while permanent customer deletion still removes all linked records to preserve its existing semantics.
- Walk-in creation and recycle-bin restoration use authenticated security-invoker database RPCs with restaurant-scoped locking and interval checks; this preserves RLS and trusted audit attribution while detecting concurrent service conflicts.
- Account deletion goes through the SECURITY DEFINER RPC delete_own_account(): it removes the caller's restaurant_members row and auth.users row while audit survives on copied operator-name text; the last active master of a restaurant is blocked from self-deletion.
- Keep .env tracked in git (never in .gitignore): it holds only publishable keys and the published build reads VITE_* values from it; ignoring it ships a blank site.
- Super Admin / assistenza: `platform_admins` + `is_super_admin()` (security definer) danno bypass RLS in lettura/scrittura su tutte le tabelle del ristorante; il contesto assistenza vive in sessionStorage (`src/lib/assist.ts`), la membership sintetizzata in `membershipQuery` rende il ristorante scelto "corrente", e ogni query dati va filtrata con `scopeAssist` perché il bypass mostrerebbe tutti i locali insieme.
